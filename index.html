Votre entrée en relation, sans un outil de plus

Ondorse reste votre table KYB, Salesforce reste l’outil des sales. Forest porte le dossier d’entrée en relation autour d’eux : le déclenchement, le suivi entre équipes, la décision, les écritures dans le core banking et la preuve.

Ce qu’on a compris

Des parcours clients digitalisés, des parcours collaborateurs à outiller

Votre situation

  • Les parcours clients sont digitalisés ; les parcours collaborateurs ne le sont pas encore.
  • Premier cas : l’entrée en relation, avec beaucoup de cas atypiques (international, banque judiciaire) et des pièces complémentaires à aller chercher.
  • Aujourd’hui, les allers-retours entre front, CSS et DRC passent par mail et par un fichier de suivi. Ce n’est ni scalable ni traçable.
  • Vous avez une équipe d’ingénierie, une couche API et votre propre back-office en construction.

Ce que vous ne voulez pas

  • Réintégrer dans un nouvel outil ce que vous payez déjà chez Ondorse.
  • Que vos équipes jonglent entre plusieurs écrans pour un même dossier.
  • Une brique externe sans valeur claire face à un développement interne.
Le process cible

Qui fait quoi, et où, du premier contact au compte ouvert

  1. Le sales lance l’entrée en relation depuis l’opportunité Salesforce. Un webhook prévient votre couche API.
  2. Forest ouvre le dossier et applique vos règles de parcours selon le profil : corporate, judiciaire, entité étrangère, crypto.
  3. Le dossier Ondorse est créé par API avec le portail adapté au profil. Le lien apparaît dans l’opportunité.
  4. Le client remplit le portail Ondorse. C’est le seul écran qu’il voit.
  5. Ondorse fait ses contrôles : registres officiels, bénéficiaires effectifs, screening, analyse des documents.
  6. Le CSS revoit le dossier dans Ondorse. S’il manque une pièce, Ondorse ouvre un portail de collecte complémentaire.
  7. Ondorse rend la décision KYB : validé ou refusé.
  8. Forest suit le dossier grâce aux événements Ondorse : statut, pièces manquantes, tâche au sales si le client bloque.
  9. La DRC décide de l’entrée en relation dans l’inbox Forest, avec double validation sur le risque élevé. Les cas hors parcours Ondorse arrivent dans une file dédiée.
  10. Forest exécute les écritures : ouverture du compte via votre API core banking, mise à jour de Salesforce. La preuve réunit l’audit log Forest et le rapport d’audit Ondorse.
Qui fait quoi

Ondorse valide le KYB. Delubac décide d’entrer en relation.

La distinction compte : un KYB validé ne vaut pas acceptation du client. Ce qui se passe entre les deux, c’est le dossier que Forest porte.

Pour votre équipe d’ingénierie

Comment ça se branche

Déclencher un workflow Forest

Chaque workflow peut s’ouvrir à un webhook. Votre système appelle une URL signée avec l’identifiant du dossier ; le run s’exécute avec les droits du jeton utilisé, et l’activity log l’attribue à ce compte.

  • Un seul run actif par dossier : un doublon renvoie 409, les relances sont sans risque.
  • Environ 60 appels par minute et par webhook, ajustable.
  • Une étape qui demande un humain part dans l’inbox prévue pour le workflow, où un opérateur la reprend.

Ondorse

Ondorse expose une API (création de dossier, portails d’onboarding et de collecte, décisions, documents, rapport d’audit) et des webhooks : changement de statut, revue ouverte ou close, collecte ouverte ou close, documents.

Votre couche API relaie l’événement : elle retrouve le dossier et appelle le webhook Forest.

Salesforce

Dans le sens Salesforce vers Forest, un Flow appelle votre couche API, qui crée le dossier puis déclenche le workflow. Dans l’autre sens, une action Forest, codée une fois dans votre agent, met à jour l’opportunité et crée les tâches du sales via l’API Salesforce.

Vos données restent chez vous

L’agent Forest tourne dans votre infrastructure, connecté à vos bases et à votre couche API : vos données restent chez vous. Les habilitations s’appliquent par rôle et par segment, pour vos collaborateurs comme pour vos comptes de service et vos agents IA.

Votre propre interface

Vous construisez l’écran, Forest garde les droits, les actions et la trace

Si vos équipes front ou CSS ne doivent pas ouvrir Forest, la Forest Gateway se déploie à côté de votre agent et ouvre deux portes sur les mêmes briques :

Une API REST pour vos applications

Listes filtrées, compteurs et formulaires d’action, avec une spécification OpenAPI générée pour votre configuration. De quoi afficher le dossier et ses actions dans votre portail interne ou dans Salesforce.

Lecture et actions. Par défaut : 300 requêtes par minute et par identité, 1 000 enregistrements par page.

MCP pour vos assistants IA

Un assistant peut chercher un dossier, lancer une action ou démarrer un workflow, toujours avec les droits de la personne ou du compte de service qui l’utilise.

Dans les deux cas, chaque appel passe par une identité. La Gateway ne prend aucune décision d’accès : votre agent applique les mêmes permissions et périmètres que dans Forest, et chaque accès est tracé.

Construire ou acheter

Ce que votre équipe n’aura pas à construire, ni à maintenir

Le plus parlant est de chiffrer cette liste en jours-homme avec votre équipe.

  • Les connecteurs Salesforce, Ondorse et core banking, et leurs évolutions de version.
  • Les habilitations par rôle et par périmètre de données, pour les humains et pour les agents.
  • La file de dossiers : répartition, délais, escalade, double validation.
  • L’audit log exportable avec les valeurs avant et après chaque écriture.
  • Un éditeur de workflows pour que vos ops fassent évoluer les process sans repasser par les devs.
  • Le changement de fournisseur : on remplace un connecteur, le dossier, les règles et la preuve restent.
Au-delà de l’entrée en relation

D’autres process sur les mêmes briques

Opérations BaaS

KYC, re-KYC et suivi de vos distributeurs et de leurs clients finaux : demandes, incidents, blocages. Xpollens et Swan font tourner leurs opérations sur Forest.

Alertes LCB-FT et risque crypto

Un agent pré-analyse l’alerte, l’analyste décide, la preuve est prête pour le régulateur.

Chargebacks et litiges

Pré-analyse automatique du dossier émetteur, les pièces demandées par les réseaux étant toujours les mêmes, puis revue humaine.

Successions

Un calcul et un dossier répartis sur plusieurs outils, repris dans un seul process avec ses validations.

Procédures collectives

Si une partie des échanges avec les administrateurs et mandataires passe encore par mail, c’est exactement un cas de dossier. À valider avec vous.

Prochaine étape

45 minutes de travail sur un vrai dossier

Pas de démo produit : on déroule ce schéma sur un dossier réel et on corrige ce qui ne colle pas. Idéalement avec vous, la PO Risque et Conformité, la personne qui porte la digitalisation et votre Head of Data.

Pour préparer :

  • Vos volumes mensuels d’entrées en relation.
  • La part des dossiers qui partent en demande de pièces complémentaires.
  • Le délai moyen entre la signature et l’ouverture du compte.
  • L’état de votre déploiement Ondorse, et ce que contient aujourd’hui le fichier de suivi du CSS.
